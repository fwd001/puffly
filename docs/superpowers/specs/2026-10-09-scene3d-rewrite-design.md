# Smoke Ritual — 界面层 3D 重写设计（TresJS + WebGPU）

2026-10-09 · 状态：待评审

## 1. 这一版要做什么

把 `apps/web` 的**界面层就地重写**：用 TresJS + `three/webgpu` 的 `WebGPURenderer` 渲染，
**整个界面进 3D 场景**（HUD、按钮胶囊、导轨、面板、卡片、列表都是场景对象），仓里不再有
Canvas 2D 的绘制路径；逻辑层（模拟、内容、声音、存档、统计）原样复用。

三项已拍板（2026-10-09）：

- **范围**：全部进 3D —— 连面板与卡片都画进场景；DOM 只留无障碍标注层与失败兜底；
- **兜底**：WebGPU 优先，不支持时**自动回退 WebGL2**（不显示"设备不支持"）；
- **落点**：**就地重写 `apps/web`**，不留双轨。线上站会在重写期内退步，这是明确接受的代价。

### 与既有约束的关系

`docs/SPEC.md` §76 的标题是「No Premature Engine」，`docs/ARCHITECTURE.md:341` 把它转写成
"no game engine dependency — Canvas 2D and `requestAnimationFrame` only"。
这一版**明文推翻它**，替代口径：

> 渲染用 TresJS + three（`three/webgpu` 的 `WebGPURenderer`，回退 WebGL2）；着色器只有一份 TSL，
> 两条后端共用；游戏逻辑仍然不许依赖任何渲染库，也仍然不许碰 DOM。

三条由此直接得出的结论：

1. **两条后端本机都能验**：WebGPU 走 localhost/https（安全上下文），WebGL2 用强制回退跑。先前
   「本机只能验回退路」已作废 —— 那是探针跑去 `about:blank` 量出来的假结论。
2. **最小场景就 421 KB（gzip）**：一个立方体 + 400 个点的 TresJS + `three/webgpu` 产物 1.52 MB /
   gzip 421 KB，而现在整个入口是 120 KB —— §8 那条「入口 gzip ≤ 400 KB」作废，改成实测口径。
3. **中文字形集小到可以按需烘**：314 个字形的 MSDF 图集放得进 512²，不需要任何中文字库文件；
   纯图标档就是那批字根本不生成。

## 3. 架构与包边界

```
apps/web            壳：TresCanvas + 隐藏 DOM 标注层；纯 TS 工具（rail/shelf/scenes/
                    archiveModel/phase/limit/haptics/i18n）原样保留
packages/game-scene  新：3D 场景 —— TSL 材质、对象图、文字图集、场景内布局、拾取
packages/game-renderer  删除：5 个纯文件迁走，7 个切"场/画"后删画
packages/game-core / game-content / game-audio / game-storage / game-statistics / shared
                    一行不动
```

- 依赖方向：`core ← scene ← web`。`game-scene` 是"脏"包（可以依赖 three、可以碰 DOM/GPU），
  `game-core` 仍然不许（`tests/architecture.test.ts` 的守卫保留）。
- **新增一条守卫**：`game-scene` 只许读 `GameStateView`，不许写回状态 —— 把今天渲染器那条
  "只读、类型禁止写回"的约定，原样换成对场景包的检查。
- 每个包一个用途、一个边界：`game-scene` 只回答"状态长什么样"，不回答"状态怎么变"。

## 4. 渲染

- 一个 `WebGPURenderer`（`three/webgpu`），初始化失败自动 `forceWebGL` 回退；**一份 TSL 着色器
  同时编到 WGSL 与 GLSL**，不写两套。
- 烟 / 余烬 / 灰 / 火改成 GPU 点精灵 + TSL；风、通风系数、释放方向仍由核心出（今天那套场原样）。
- 道具（烟盒、打火机、烟灰缸、桌子）从"离屏 canvas 烘焙贴图"改成**真几何 + 材质**。
- 分级沿用今天 `quality` 档位的语义（高/平衡/轻），映射到粒子预算与分辨率；静止降帧保留。
- 首帧：点火前要有加载态（不是黑屏）。

## 5. 输入与命中

- 指针 → 射线拾取，命中集合就是核心已经发布的那套锚点与手势词
  （`pick` / `light` / `hold` / `flick` / `press` / `drop`）—— 核心不用知道有射线这个东西。
- 手势在场景层实现：按住吸入、拖动、下滑收界面、双指掐灭、长按 0.6 秒开档案、轻磕与掐灭。
- 场景把状态镜像成**机器可读的字段**（今天 `.stage` 上那套 `data-*` 的等价物），真机套件改读它。
- 键盘路径（`Space` 按住 / `Enter` 点 / `Esc` 掐灭 / 方向键移动）保留，由隐藏 DOM 层承接。

**已经验到的（临时工程 `/tmp/puffly-spike`，2026-10-09）**：文字进 3D 成立 —— 从烘好的图集建
「一个字一个四边形」的网格，在 TresJS + WebGPU 场景里画出 `烟种图鉴 4 / 11`（截图在
`/tmp/puffly-spike/text-in-3d.png`），165 帧、零报错。两条踩出来的坑记在这里：① 字形集要按
**可打印 ASCII（0x21–0x7e）+ 汉字 + 全角标点**取，只取 `[A-Za-z0-9]` 会漏掉 `/`；② 图集的墨色与
材质颜色是**相乘**的，黑墨 × 白材质 = 黑字，烘的时候就要按最终用法定颜色。另：那张演示图里的字距是按 advance 粗裁 UV 的
（宽字会被压窄），**真做的时候要按每个字自己的包围盒建四边形** —— 图上看着"能读"不等于排版对了。

**射线拾取：还没归因，带全部读数交棒（并且我推翻过自己一次）**。spike 里文字打不中，逐次读数：

| 探针 | 读数 | 说明 |

| 同一根射线打**文字网格**（手搓索引） | 0 次 | 几何顶点 28 / 索引 42 / 包围球 1.414 / 世界盒子与射线全对 |

结论到此为止（六轮假设后停手）：**同一根射线打 three 自带的平面中、打我的文字网格不中，两种构造都不中**
⇒ 嫌疑收敛到**文字几何的构造**本身；最小复现留在 `/tmp/puffly-spike`（28 顶点 / 42 索引 / 带贴图材质）。
**计划里「输入与命中」的第一步先照抄这个 spike 的对照跑一遍**（stock PlaneGeometry 中 ⇒ 尺子是好的），
再逐步换成真实文字网格，每一步都要看见命中数落在预期上。**实施计划的「输入与命中」一步必须从对照实验起步**：
先用一个已知良品（`PlaneGeometry` 的普通 Mesh）证明"我的射线/相机/矩阵这一套尺子看得见东西"，再往上
叠文字、叠面板；在那之前，任何"拾取不工作"的说法都不算结论。## 6. 界面在场景里怎么组织

- 一层屏幕空间布局（正交相机）：布局单元=行/列/间距/最小触控 54px/文字层；所有面板共用。
- HUD 行、按钮胶囊、底部导轨、四张面板、档案卡都是这层里的对象；它们的**规则照搬**，因为规则
  是从核心状态推出来的：静止 2.6 秒界面自收、开面板顶掉胶囊、点场景收面板、无字层只留记号。
- 面板内滚动自己实现（拖拽 + 惯性），沿用今天那条"分组条"的语义与最小触控。

## 7. 文字 / 无障碍 / 三档语言

- **文字（管线已实测，见下）**：构建期从 `apps/web/src/i18n/copy.ts` 生成字形图集 ——
  `fontkit`（读字形轮廓，纯 JS）→ SVG → `@resvg/resvg-js`（光栅化，预编译二进制）→ 图集 PNG + 一份
  下标 JSON。没有 canvas、没有 Java、没有中文字库进包。语言切到「纯图标」档时不生成那批字形。
  **现量读数**（临时工程 `/tmp/puffly-spike/bake-atlas.mjs`，输入就是本仓的文案表）：
  359 个字形（314 汉字 + 拉丁大小写 + 数字 + 全角标点）、20×18 格、1280×1152 px、PNG **≈ 0.4–0.5 MB**、
  轮廓 41–148 ms + 光栅 0.6–1.9 s。放大看一眼：字形干净、没有缺字（tofu）。
  ⚠️ **发版要换字体**：这一版烘的是系统字体 STHeiti（Apple 的，不许随包分发）。上线用 Noto Sans SC
  （SIL OFL，可分发）；字形集只由文案表决定，换字体只是重烘一次。
- **无障碍**：一个隐藏 DOM 层镜像所有可交互对象（`role` / `aria-label` / 焦点顺序），
  **与场景对象由同一份清单生成**——不许两处手写，否则就是今天"同一判据两个家"的老毛病。
- **判据**：字号那条从"CSS 声明 ≥15px"改成"图集字号 × 世界缩放换算到屏幕像素 ≥15px"，
  并配一条反证（把缩放调小，那条判据必须红）。

## 8. 判据与门禁怎么换

**失效的**（读 canvas 像素的那些）：`packages/game-renderer/src/__tests__` **34 个文件里读像素的 19 个**
（`ash-flake` `background-stillness` `choice-pixels` `ember-glow` `ember-heat` `ignition-punch` `lid-hinge`
`pack-object` `paper-dimple` `place-features` `plume-column` `plume-contrast` `plume-lift` `prop-placement`
`rain-fall` `realism` `rendering` `scene-change` `warmth-scale`）；
另 **13 个是纯的**（`plume-shape` / `plume-continuity` / `plume-on-stage` / `plume-palette` / `chrome-band` /
`rod-anchor` / `skin` / `spark-bounce` / `sprite-focus` / `char-edge` / `custom-background` / `platform` —
它们量的是几何与派生量，不读像素），**跟着模块搬进 `game-scene`，不失效**；
真机套件里 4 处读 canvas（`getImageData` / `toDataURL`：`airSample` / `cloudStructure` / 场景翻转那些）。

**替身三层**：

1. **场景图断言**（单测，three 可无头跑）：对象在不在、位置、材质参数、可见性、镜像字段；
2. **真机截图读像素**：整页截图代替 `getImageData`，"一口气有明有暗""烟羽是一条线"这类
   图形判据换个读法留下来；
3. **24 屏追平清单**（见 §9）：一屏一行，逐屏验收。

**门禁（六步）保留**，另加两条：

- **包体上限（按实测，不按估计）**：最小 TresJS + `three/webgpu` 场景 = 1.52 MB / **gzip 421 KB**，
  而今天整个入口 = 120 KB（读数来自临时工程 `/tmp/puffly-spike`）。预算写成「首屏可交互资源
  ≤ 700 KB gzip，且场景块单独切出来懒加载」，超了要红；
- **两条后端**：真机套件跑两遍（本机只能跑 WebGL2；WebGPU 那遍见 §11）。
